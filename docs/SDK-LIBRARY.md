# Astra SDK Core 0.2.0-alpha.1

Независимый optional library-пакет для Foundry v12. Структура устанавливаемого архива собрана; загрузка в настоящем Foundry ещё не проверена. `compatibility.verified` намеренно отсутствует.

Внутри — ровно те же исходники ядра, которые используются боевым стендом, журналом и базой: OperationEngine, state machine, typed errors, canonical JSON, MemoryStore/IndexedDBStore, public projection. Добавлены Scope/RefreshScheduler для владения подписками и очистки. В пакете нет правил Cyberpunk RED, renderer боевого HUD, Studio, socket transport, медиа или собственного игрового workflow.

Исходники SDK скопированы без изменений; `SOURCE-HASHES.json` фиксирует SHA256. Библиотека не регистрирует автоматические игровые операции или настройки мира. Единственная интеграционная запись при init — `game.modules.get('astra-sdk-core').api` в памяти клиента.

## Использование

После ручной установки в независимый LAB:

```js
const sdk = game.modules.get('astra-sdk-core').api;
const store = new sdk.IndexedDBStore({
  name: `astra-lab-${game.world.id}-${game.user.id}`
});
const engine = new sdk.OperationEngine({
  store,
  descriptors: [myTrustedAdapter],
  executorId: `client-${game.user.id}`
});
```

`myTrustedAdapter` должен реализовать проверку входа, права, preview и конкретный executor. `principal` должен формировать доверенный порт; библиотека не превращает введённое пользователем `role:'gm'` в настоящие права. Схемы в каталоге описывают операции; фактическую проверку реализует `descriptor.validate`.

Default IndexedDB доступен только клиентам одного origin/профиля. Разные пользователи Foundry на разных компьютерах **не получают общее хранилище** от установки библиотеки. Нет серверной аутентификации, выбора GM-лидера или постоянного сервиса. После закрытия всех клиентов таймер не исполняет операцию: восстановление сравнит сохранённый deadline при следующем запуске. Для нескольких исполнителей требуется общий CAS store и авторитетный источник времени.

Проверка fencing перед отдельной записью документа не даёт общей атомарности. Нативный адаптер обязан обеспечить собственный идемпотентный commit/receipt или перевести сбой в `uncertain`. Поддерживаемая компенсация конкретного адаптера не является универсальным откатом.

## REDLINE и зависимости

Текущая REDLINE alpha содержит исходники ядра для самостоятельного локального стенда; нативный HUD вызывает только чтение и предпросмотр. Поэтому optional SDK Core не требуется для её включения. Это осознанная ранняя сборка: после проверки Foundry port следующий релиз сможет вынести runtime imports в библиотеку и добавить `relationships.requires` с проверенным диапазоном версий. Пока такая обязательная зависимость не заявлена.

Manifest `library:true` соответствует схеме Module v12: https://foundryvtt.com/api/v12/classes/client.Module.html . ZIP локальный; manifest/download URL и опубликованный релиз отсутствуют. Из одной ссылки на сервер нельзя установить этот архив через браузерный manifest installer.

Установка библиотеки сама не подключает чат или агента к Foundry. Машиночитаемый каталог описывает локальный API; авторизованный внешний bridge/MCP и доступ агента к среде — отдельная интеграция, не входящая в этот пакет.

Сборка из исходного комплекта: `python3 tools/build-sdk-library.py`. Проверки исполняются в родительском alpha2 комплекте. MIT; сторонний GPL-код не переносился.
